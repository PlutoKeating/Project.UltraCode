# UltraCode 架构

## 1. 目标

UltraCode 解决两类问题：长程工程中的目标漂移、上下文腐烂与自评宽容；以及增强链路在新机、已有复杂配置和 OpenCode 官方升级后的可重复安装。

核心约束：Provider/Model 中立，不读取凭据，不做真实模型安装测试，不侵入官方二进制。

## 2. 长程工作流

```text
用户目标 / Spec
  → Superpowers：澄清、TDD、系统化调试
  → OpenCode 原生 Planner / Architect
  → Implementer / 原生后台子代理
  → 独立 Reviewer / Visual Evaluator
  → Ralph 外层全新 opencode run
  → Git、任务、Progress、Handoff 持久化
```

子代理隔离会话内上下文，Ralph 在顶层迭代之间创建新会话。二者不可互相替代。

所有角色不包含 `model`，Ralph 不传 `--model`。用户当前 OpenCode 会话决定实际 Provider 与模型。

## 3. 分发模块与接口

```text
                  小接口
        apply / sync / doctor / update / up / uninstall
                         │
      ┌──────────────────┼──────────────────┐
      │                  │                  │
 Install Module     Config Module      Release Module
 文件所有权/卸载     最大并集 JSONC       稳定版本/SHA256
      │                  │                  │
 Runtime Module     OpenCode Adapter    Website Module
 私有运行时/浏览器   版本/官方升级        Stable/Next 双语站点
```

接口只暴露调用者需要的操作；平台、路径、备份、锁版本、原子写入和验收属于内部实现。

## 4. 最大并集合并

- 对象递归补缺失键。
- 数组按值去重追加，避免重复权限和插件。
- 已有不同标量保留并报告。
- JSONC 注释、未知字段、Provider、凭据引用和用户 MCP 原样保留。
- Agent、Command、MCP 使用 UltraCode 命名空间。
- 清单哈希区分上游旧文件与用户本地修改。
- 卸载仅精确删除未修改的 UltraCode 所有状态。

## 5. 私有运行时

独立编译 CLI 内嵌 Bun 能力。安装器以子进程方式使用同一二进制安装固定版本 Ralph 与 Playwright，无需用户预装 Node/Bun，也不写全局包目录。

Superpowers 与 Ralph 的固定源码归档具有 SHA-256；Playwright 使用精确 npm 版本。浏览器存入 UltraCode 数据目录。

## 6. 官方升级接缝

OpenCode 二进制只由官方安装脚本或 `opencode upgrade` 管理。

- `uc up`：显式执行官方升级，再更新 UltraCode 并 sync。
- `uc sync`：官方 `/update` 或安装脚本后的幂等修复。
- `uc doctor`：结构、版本、文件和运行时检查，不调用模型。

当前测试基线为 OpenCode V2.3.x；更新的 V2 只承诺结构检查，未来大版本需要显式适配。

## 7. 网站与发布

Astro Starlight 从单一内容源生成中文/英文 Stable/Next 路由，并把根 `install.sh` 复制到静态站点。Cloudflare Workers Static Assets 发布 `website/dist`。

维护者为稳定 tag 手动触发 Release 工作流，使用一个 Linux Runner 交叉编译四种目标，在宿主执行版本冒烟，生成 SHA-256 与 Artifact Attestations。CI 不使用真实模型、用户凭据或 Docker。

## 8. 下一版普通对话工作流的产品决定

- 以官方 TUI 为首发验收入口。安装后增强可执行主会话，保留用户自定义角色和只读约束。用户用自然语言走完整个流程，新入口和教程移除旧斜杠命令。
- 由模型根据当前目标、用户指令和上下文，自主决定何时规划、实施、评审，何时创建、修改、暂停或移除短期及长期目标。路由建议进入提示词，程序提供会话、存储、权限和取消等执行能力。
- 开工前先读仓库。涉及范围、验收或不可逆决策时集中调研并一次问齐，尽量提供带建议的选择题。原文见主角色配置。其余选择由模型判断。
- 从多次反馈中学习长期偏好，支持用户查看与撤销。用户以产品经理或架构师视角表达受众、业务链路、模块协作与验收；原对话默认只呈现里程碑、阻塞和结果，细节按需查看。
- 用户关闭终端后，已接受的任务可继续。服务重启后展示恢复点，用户可用自然语言续跑。明确叫停要阻止后续调度。对插话、改目标和重新规划的处理由模型结合当时语境判断。
- 默认当前工作区串行写入，有必要时隔离到 linked worktree。保留用户已有改动，无 Git 或无法无损隔离时避免擅自迁移。普通任务留 diff，隔离长跑可本地提交，带回原分支前询问；遵守仓库自己的 Git 规则。
- 默认继承会话模型，尊重已有角色映射和用户自然语言指定。提示词向模型说明可用模型池，让模型根据领域、难度和目标明确程度选择。程序不维护领域到模型的硬编码路由表。
- 按真实进展判断续跑。持续接近目标的任务可运行几十小时。公共版不施加默认强制时间、轮次或资源预算；长期重复劳动时重新评估并说明阻塞。
- 按任务验收。复杂改动独立评审，用户可见交互必须实际操作并目视检查渲染结果。运行浏览器测试或保存截图之后还需检查用户实际看到的界面。
- “命令执行与权限审批”和“方向性的决策询问”各自支持 manual / auto，auto 表示自动批准。界面可独立快速切换。权限默认 auto，方向询问默认 manual。宿主 deny 保持生效。
- 长跑在仓库内保存可提交的任务、进度与交接文件，便于团队接力。提示词要求提交使用用户配置的 Git 身份，并遵守用户显式禁止提交或署名的指令。
- 短程隔离冒烟通过即可发布，由维护者亲自从安装开始体验。开发测试使用隔离用户目录和服务，保护维护者已有 OpenCode 二进制与个人配置。

安装器按插件身份、权限的 action/resource 和 MCP 启动配置识别冲突。等价的 Playwright MCP 可复用，视觉评审角色使用对应的工具名。配置清单记录安装器实际添加的字段和数组成员。旧版清单通过可验证的安装前备份迁移；来源无法确认时保留原值。

`uc doctor` 检查当前项目实际注册的角色、Superpowers 和 UltraCode 插件的活动状态，以及所选浏览器 MCP 的连接状态。

主角色 `uc-apex`（总协调与执行，默认）和 `uc-atlas`（规划）直接安装在 `agents/`，可用 Shift+Tab 切换。
