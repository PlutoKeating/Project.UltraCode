This lesson solves something very practical: **the work has started, but you have to leave the desk.**

You do not need remote desktop, and you do not need to carry the laptop. A phone browser can take over the same progress.

## <span class="uc-step-no">01</span> Create a pairing link on the computer

Copy that link and send it to yourself in a phone chat window — the most reliable way to move it across.

<CommandBlock
  label="Type this in the terminal — the only line you need"
  command="ultracode pair"
  copyLabel="Copy"
  copiedLabel="Copied"
/>

**What you'll see:** One link appears that you can open directly. It stays valid for a few minutes only.

## <span class="uc-step-no">02</span> Open it on your phone

Nothing needs to be installed on the phone. The interface reshapes itself for finger-sized taps.

**What you'll see:** The same project opens in your phone browser, with the same project name and the same progress.

## <span class="uc-step-no">03</span> Answer its questions right on the phone

So the moments that actually need you are never missed: picking a style, choosing an approach, deciding whether to continue.

**What you'll see:** Choice cards are just as tappable on a phone, and the desktop updates as soon as you choose.

## <span class="uc-step-no">04</span> Prefer fewer interruptions? Flip the two switches

The other switch is `/approvals`, which controls whether it asks before running an action. Both stay in sync between computer and phone.

<CommandBlock
  label="Send this command in the phone composer"
  command="/direction"
  copyLabel="Copy"
  copiedLabel="Copied"
/>

**What you'll see:** The current questioning mode is shown and switches immediately: let it decide on its own, or have it ask you every time.
