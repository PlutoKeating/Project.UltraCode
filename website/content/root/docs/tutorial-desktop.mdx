In this lesson we do exactly one thing: **build a working weekend book-club sign-up page inside an empty folder.**

No commands to memorise, no programming knowledge required. You click a few times, then describe what you want the way you would to a colleague.

<div class="uc-tut-goal">
  <span class="uc-tut-goal-label">What you end up with</span>
  <p>A sign-up page you can open in a browser, still comfortable to use on a phone.</p>
</div>

<TutorialStep
  step={3}
  title="Answer the cards, then let it check its own work"
  expectLabel="What you'll see"
  expectText="After building a first version it opens a real browser, clicks the buttons, checks both desktop and phone layouts, and reports back. Accept it once you see that check pass."
>
  When a choice card appears, click whichever option matches your intent; if you are unsure, take the recommended one. Then it moves forward in small steps, and you can interrupt at any moment.
</TutorialStep>

<TutorialStep
  step={4}
  title="Not happy? Keep talking instead of starting over"
  promptLabel="Ask for a style change like this"
  promptText="Make the whole thing calmer, use a warmer heading colour, make the button bigger, and keep it on one line on a phone."

  expectText="Only the colours and layout change; the sign-up logic you already approved stays intact."
>
  This is the difference between describing a **goal** and writing code: you describe the outcome, and it handles implementation plus self-checking.
</TutorialStep>
